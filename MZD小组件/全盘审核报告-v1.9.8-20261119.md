## 二、需要你拍板的一项（本次新发现，非历史取舍）

### 【中】账号登录成功后未回写车号输入框，手工保存时可造成 token / carid 错配

- 位置：`MainActivity.java:584-610`（`doLogin()`）、对比 `MainActivity.java:572-581`（`applyResult()`）
- 问题：`applyResult()`（Root 导入路径）在成功后会 `etCarid.setText(r.carid)`；但 `doLogin()`（账号密码登录路径）成功后只 `refreshStatusText()`，没有把服务端返回的 `r.carid` 写回 `etCarid`。
- 触发路径：
  1. 先用 A 账号登录（Prefs 存 A 的 token+carid，但输入框 carid 仍是旧值/空）；
  2. 切到 B 账号再次登录成功（Prefs 更新为 B 的 token+carid，输入框 carid 依旧是旧值）；
  3. 用户在输入框改动 token 或点"保存 Token" → `doSaveToken()`（`MainActivity.java:613-627`）把**新 token + 旧输入框 carid** 一并 `Prefs.saveToken()`。
- 后果：token 与车号来自不同账号，所有 `/car/status` 与控车指令打到另一台车或返回 401。属凭证一致性问题，不泄露数据。
- 建议：`doLogin()` 成功回调里补一行 `etCarid.setText(r.carid)`，与 Root 路径对齐。**这是唯一建议修改的源码点，等你确认后我再动。**

## 三、已知取舍的回归（v1.9.9/v1.9.10 曾修，按你要求已回滚，本次仅报告不改）

> 说明：你明确要求"恢复 1.9.8、不要乱改、扫不到时自己在系统蓝牙删除配对即可"。以下均属当时那两个版本修复、随回滚一起消失的问题。列出供你知情，**除非你另行指示，我不会再改**。

### 【严重·安全】扫描失效时静默超时可能上锁，存在把车内人员锁住的风险

- 位置：`BleScanService.java:348-370`（看门狗判离开）+ `CarActions.java:351-395`（`onBleAbsent`）
- 触发：设备被系统蓝牙连接后停止广播 → App 持续扫不到 → `silent` 累积到阈值 → `setPresent(false)` → 上锁判定；此时 `started==false && unlocked==true` 就会下发 lock。若人仍在车内（熄火休息、后排有人、刚上车未启动），会被锁住。
- 现有防线覆盖不了：车况查询失败/`started==null` 时会跳过，但设备停播时车况本身是好的（能查到未启动+门开着），防线不触发。
- 你的既定处置：在系统蓝牙删除配对即可解除连接、恢复广播。App 侧维持 v1.9.8 的扫描行为。

### 【高】退避被 onStartCommand 绕过，可能撞 Android"30 秒 5 次 startScan"配额

- 位置：`BleScanService.java:434-450`（`startScanInternal` 未检查 `restartAt`）+ `onStartCommand:291` + `MainActivity.java:236-238`
- 触发：反复进页面/切开关 → 每次 `onStartCommand` 直接调 `startScanInternal` 而忽略失败退避 → 30 秒内注册超 5 次 → 后续 `startScan` 被系统静默拒绝、无回调。
- 缓解手段：关→开蓝牙或删除配对后重选设备可复位。

### 【高】自愈重启传 resetState=true 清掉 present

- 位置：`BleScanService.java:338`（`startScanInternal(true)`）
- 触发：蓝牙从关→开时重置在场状态。若此时用户实际已远离车辆，present 被清后本次停靠周期不会按"离开"下发上锁（该上锁时漏锁）。属"宁漏不误"方向，风险低于误锁。

### 【中】onScanFailed 未清残留注册

- 位置：`BleScanService.java:182-195`。失败时只把 `scanning=false`，未 `stopScan`；Fragment 侧可能残留半注册状态，配合退避绕过放大配额问题。

### 【中】自愈判定用 lastResultAt 而非命中目标

- 位置：`BleScanService.java:99/137/342`。周边有其他 BLE 设备时任意回调都会刷新 `lastResultAt`，"60 秒零回调自愈"永远不触发。定向硬件过滤下此场景较少。

### 【低】零回调时诊断不落盘 + 关键节点被 5 秒节流吞

- 位置：`BleScanService.java:347`（`if (diagCb.get()>0) persistDiag()`）+ `555-561`。真正扫不到时主界面诊断计数冻结在旧值，排查信息失真。
