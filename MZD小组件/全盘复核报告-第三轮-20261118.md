## 一、本轮修复的真实问题（8 项）

| # | 文件 | 问题 | 修复 |
|---|------|------|------|
| 1 | `MainActivity` + `CarStateCache` + `CarWidget` | **切号/换车旧车况冒充**：登录、登出、Root 导入、换 Token 只改凭证，不清全局缓存与桌面写盘状态。切到账号 B 后 `snapshot()` 仍返回账号 A 的车况，`refreshAndUpdate` 当作实时写盘显示 | 新增 `CarStateCache.invalidate()`（清 cached/lastError）、`CarWidget.clearStatusOnCredentialChange()`（清 KEY_STATUS_JSON/ERR）；四处凭证变更统一调 `onCredentialChanged()` |

## 二、代理上报但经核实**不修改**的项（取舍 / 误报 / 夸大）

| 发现 | 核实结论 |
|------|----------|
| **goAsync 承载一键启动/CMD 会超时中断流程**（显示层代理标高危） | **夸大**。Android `goAsync()` 超时只结束广播槽位并记录超时，**不会杀掉独立的 `new Thread` 子线程**；`smartStartAndUnlock` 有完整 try/catch/finally，流程会跑完，SMART_RUNNING 也会复位。进程在后台时确有被回收风险，但改成前台服务是大改动，且桌面按钮触发时进程因组件更新处于活跃态。列为已知风险，不改。 |
| `snapshot()` 与 `lastError()` 两次独立加锁竞态可能抹掉失败提示（显示层代理标中危） | **真实但窗口极窄**：两次加锁之间须恰好完成一整轮网络失败查询并回调 writeStatusError，而 `refreshAndUpdate` 本身是毫秒级同步操作。后果仅一次显示闪烁，下轮 `onGlobalStatus` 立即纠正。修需重构 CarStateCache 接口，列为取舍。 |
| 冷启动 `s==null` 分支显示 prefs 旧 JSON 而非"正在获取"（显示层代理标中危） | **真实但语义取舍**：显示"上次成功车况"比"正在获取"更有用，且 `KEY_STATUS_ERR` 为空说明上次是成功查询。切号场景的旧值问题已由本轮 #1 的 `clearStatusOnCredentialChange` 解决。不改。 |
| `exportCred` 每次 new Thread 无串行化（支撑层代理 BUG-4） | 可疑，实际触发需短时间内多次登录/导入，且 CredFile 内部 deleteOld→insert 有 IS_PENDING 保护。低概率，列为取舍。 |
| root `parseMmkv2` 的 klen 越界用 break（BUG-7） | 可疑，反方（文件尾部 break 是正常结束）成立，且解析已从真实 data 包验证。不改。 |
| `picked` 集合跨线程无同步（显示层代理 BUG-9） | 低危可疑，扫描停止与遍历的窗口极小，且 LinkedHashMap 读多写少。不改。 |
| MediaStore 写入失败 IS_PENDING 残留（支撑层代理 BUG-3） | 真实但低概率，主路径有 try-catch 兜底直写。列为取舍。 |
| 诊断时间差 wall-clock 校时回退显示负值（BUG-9） | 低危显示问题，跨进程需 wall-clock。不改。 |
| 后台启动前台服务被 Android 12+ 拒绝（BLE 层代理发现4） | 平台/ROM 行为，属可疑，需实机多 ROM 验证。不改。 |

## 三、确认实现**正确**、无需改动的点（代理误报预防）

- `Api.getStatus` 的 `engine==3` = 已启动、`lock.lf/lr/rf/rr` 任一 `==1` = 未锁，符号与逆向文档一致，正确。
- 全局缓存 `successSeq < target` 能正确区分"本轮失败"与"旧成功"，绝不拿旧缓存冒充判定结果。
- 一键启动三步状态机、`statusUnavailable` 分类、`queryWithRetry` 重试一次、行驶中 `started==true` 绝不自动解锁——安全底线均完整。
- BLE 靠近/离开失败保守跳过、闩锁仅在发锁车命令或确认已锁时复位、v1.9.3 present 卡死修复——均正确。
- RSSI 阈值范围钳制、127 哨兵排除、`recently` 窗口、`goAsync` 六个分支的 `finally{ pending.finish() }`——均正确。
- 签名 `checkBusinessError` 抛的是 `java.lang.Exception`，不会被 `catch(JSONException)` 吞掉，能正确向上传播。
- `CarWidget` exported=true（收系统 APPWIDGET_UPDATE）、`WidgetActions` exported=false（收自定义 action）——越权面已封堵。
