## 一、本轮确认并修复的 bug（2 项）

### BUG-R1（严重·安全回归）　行驶中 BLE 重扫到目标会自动开门

- **位置**：`CarActions.onBlePresent()`
- **引入点**：上一轮 v1.8.3 的 BUG-3 修复——把判定改为「车明确已锁 → 无条件清闩锁 + 发解锁」，但**漏判发动机状态**。
- **复现链**：
  1. 用户启动车辆行驶，很多车启动后自动落锁 → 车况 `started=true, unlocked=false`。
  2. 行驶中 BLE 瞬时漏扫（遮挡/信号抖动/Doze），看门狗 `silent` 满阈值 → `present=false`，触发 `onBleAbsent`；它查到 `started=true` → 按设计「保持现状、不锁车、闩锁保持」。
  3. 下一秒 BLE 重新扫到目标 → `present` 翻转 true → 触发 `onBlePresent`。
  4. v1.8.3 逻辑查到 `unlocked=false`（车已锁）→ **无条件发 unlock → 行驶中车门被打开**。
- **危害**：行车中开门是严重安全问题。
- **修复**：把 `started==true`（发动机已启动）提为 `onBlePresent` 的**最高优先级跳过项**，命中即直接返回、不解锁、也不置闩锁。放在「车已解锁」「车已锁」判定之前，确保行驶/怠速态永不触发自动解锁。
- **兼容性**：不影响 v1.8.3 的「熄火回家闩锁卡死」修复——熄火后 `started=false`，仍能走到「车已锁 → 解锁」分支。

### BUG-R2（一致性·安全）　车况字段全 null 时离开会盲锁

- **位置**：`CarActions.onBleAbsent()`
- **根因**：`Api.checkBusinessError()` 只拦截业务码 401；服务端返回 HTTP 200 但其它业务失败码 / 字段缺失时，`Api.getStatus()` 解析出的 `started`、`unlocked` 同时为 `null`。旧逻辑里 `started==true` 不成立、`unlocked==false` 也不成立 → 落到最后的「其余 → 发 lock」分支，**在无法确认车是否在行驶的情况下盲发上锁**。
- **冲突**：判定清单 §6 明确写「车况查询失败一律跳过上锁、绝不盲锁」，此处是隐含失败态的漏判。
- **修复**：在 `onBleAbsent` 增加前置判定——`s==null || (s.started==null && s.unlocked==null)` 时跳过上锁、闩锁不变，等下次看门狗用有效车况再判。
- **说明**：这是上一轮报告「待拍板第 1 项」，本轮按「绝不盲锁」的既定设计原则直接修正。

## 二、复核后确认「非 bug / 设计取舍」的点（未改）

1. **诊断计数触发即加、非实际发出**：`diagUnlock/diagLock` 在派发线程前自增，若 `onBlePresent/onBleAbsent` 内部因条件跳过（行驶中/已锁/车况未知），计数仍 +1。通知栏文案为「解锁/上锁动作次数」，严格说是「触发判定次数」。属诊断精度问题，不影响控车正确性，未改。
2. **一键启动每轮 2 次 /car/status**：~~`query()` 查一次，`requestFastRefresh()` 的快刷 tick 又查一次。上一轮已提出，用户未拍板，本轮不动。~~ **v1.8.5 已修复**：用户拍板改，要求间隔 ≥2-3 秒。改为 `query()` 结果复用写桌面缓存、`requestFastRefresh`/`startFastRefresh`/收尾 `refreshAndUpdate` 全部移除，轮询改 3 秒 + query 内 3 秒硬节流。每轮仅 1 次请求。
3. **闩锁落盘用 commit、在场状态用 apply**：`setBleUnlockLatched` 同步写（关键控制状态），`setPresent` 异步写（重启有 10 秒窗口兜底）。取舍合理。
4. **`present` 进程重建恢复为 true 时 `lastSeen=now`**：避免刚恢复就被判离开误锁，设计正确。
5. **熄火但人一直在车旁不触发解锁**：`present` 未翻转，不重复下发。符合「一次靠近只解锁一次」。
6. **`WidgetActions.ACTION_SMART_UNLOCK` 只记日志不发指令**：v1.8 起兜底闹钟停用，保留分支仅为消化覆盖安装的残留闹钟，正确。
7. **10 秒窗口不落盘、进程重启归零；熄屏 90 秒固定；重发次数上限**：均为已确认的设计取舍。
