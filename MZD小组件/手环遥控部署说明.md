# 小米手环9 Pro 遥控控车 — 部署说明（v1.9.26）

## 能做什么 / 不能做什么

**能**：
- 短按「解锁」「上锁」，经手机中转下发到车，手环显示结果并振动反馈（成功短振 / 失败长振）。
- **长按第三个按钮 3 秒触发一键启动**：手环本地倒计时，提前松开即取消；满 3 秒才带 `holdMs=3000` 上报，手机端二次校验后复用完整三步流程（预锁车→确认启动→解锁）。手环会先回「启动流程已开始」，流程结束再回最终结果。

**不能**：
- 短按/误碰不会着车：不带 `holdMs>=3000` 的 start 指令手机端直接拒绝。
- 不支持 stall / search 等其他车辆指令。
- 手环本身无网络，必须依赖配对手机在线、MZD App 在后台运行、手环遥控开关打开。
- 开发环境没有你的手环，长按与显示修复只做了编译 + 逻辑核验，需实机确认。

## 原理

```
手环 Vela 快应用(JS)
   │ system.interconnect（蓝牙透传）
   ▼
手机 MZD App · WearRelayService（常驻前台服务）
   │ CarActions.send()（与桌面按钮同一条指令入口，写日志/提示音/安全判定全复用）
   ▼
服务器 → 车
```

小米互联的硬性要求：**手环 rpk 与手机 App 包名相同、签名证书指纹相同**，否则系统拒绝通信（报「签名不正确 / fingerprint」）。本工程已满足：
- 两端包名均为 `com.example.mzdwidget`
- 手环 rpk 的 PEM 由手机 App 的 `~/.android/debug.keystore` 导出，指纹 `750eeaa9c13e5c3f9f51d5b03ba791d76474dc966f0a2c0557ec3194c65ad094`，与 APK 一致

## 部署步骤

### 1. 手机端（MZD App）
1. 安装交付的 `MZD控车小组件.apk`（v1.9.26 及以上），覆盖安装即可，签名不变。
2. 打开主界面，**登录车辆账号**（手环指令要用已保存的 token/carid）。
3. 在设置区找到并勾选 **「启用小米手环遥控（解锁/上锁）」**。
4. 确认手机上的**小米运动健康 App 已与手环正常配对连接**。
5. 允许 MZD App 后台运行 / 电池优化白名单（root 可执行 `dumpsys deviceidle whitelist +com.example.mzdwidget`），保证转发服务不被杀。

### 2. 手环端（rpk）
1. 手机安装 **Notify for Mi Band / Notify for Xiaomi**（应用商店搜 "Notify for Mi Band"）。
2. 打开 Notify → 进入设备页 → 选 **第三方应用（Third party app）** → 上传 `mzd_band_remote.rpk`。
3. 手环上会出现「MZD控车」应用，打开即可看到解锁 / 上锁 / 一键启动三个按钮。
   > 这是新版本（versionCode 2），若手环上已有旧版 rpk，先卸载旧应用再上传，避免资源缓存导致界面重影。

> 备选安装方式：ADB 侧载（调小米运动健康的隐藏 ThirdAppDebugFragment）或官方商务对接渠道。Notify 上传最简单，推荐。

### 3. 验证
- 手环首页显示「● 已连接手机」→ 互联通了。
- 点「解锁」：手环显示「解锁发送中…」，约 1~3 秒后变「已发送」+ 短振；失败显示原因 + 长振。
- 长按「一键启动」：显示「启动中 3s → 2s → 1s」，满 3 秒才发指令，随后显示「启动流程已开始」；手机完成三步流程后手环再收到最终结果（若期间没发新指令覆盖 reqId）。中途松手显示「长按需 3 秒」且不下发。
- 手机主界面底部「查看指令日志」里会看到「手环遥控解锁 / 手环遥控上锁 / 长按3秒触发一键启动」的记录，与桌面按钮日志同格式。

## 已知限制与排错

| 现象 | 原因 / 处理 |
|---|---|
| 手环显示「未连接手机」 | 手机 MZD App 手环开关没开 / 转发服务被杀 / 小米运动健康没配对。检查 1.3~1.5 步。 |
| 回执报「签名不正确 / fingerprint」 | 手机 APK 与手环 rpk 签名不一致。必须用同一份 debug.keystore 导出的 PEM 重打 rpk，改签名后两端都卸载重装。 |
| 点按钮超时无回执 | 手机不在线 / CarActions 网络请求失败（token 失效、无网络）。看手机指令日志。 |
| 点按钮提示「操作过快」 | 内置 3 秒节流，防误触连发，正常现象。 |
| 长按启动后只看到「启动流程已开始」，没看到最终结果 | 手机三步流程还在跑（每步状态确认要几秒到几十秒）；若期间又按了新指令，旧 reqId 的最终回执会被手环忽略，以手机指令日志为准。 |
| 按钮文字出现重影/彩色条纹 | v1.9.26 已改固定 class / 固定文本节点。若仍出现，先卸载手环旧版 rpk 重装 v1.1.0，并确认手机端是 v1.9.26。 |
| 提示「未登录」 | 手机 MZD App 未登录车辆账号，先在手机端登录。 |
| Notify 里上传失败 | 确认 rpk 是为手环9 Pro 构建的；Notify 版本要支持 Vela 三方应用上传。 |

## 源码与重新构建

**两个不入库的依赖**（源码仓库不含，需本地补齐）：
1. **小米互联 AAR**：`mzdwidget_build/app/libs/xms-wearable-lib_1.4_release.aar`（闭源，104KB）。从 https://www.mibandnotify.com/xiaomi-mi-band/xms/xms-wearable-lib_1.4_release.aar 下载放到该目录。没有它手机端编译不过。
2. **手环签名 PEM**：`mzdwidget_build/band_app/sign/{debug,release}/{certificate,private}.pem`（私钥，绝不入库）。从手机 App 的 `~/.android/debug.keystore` 现场导出，命令见下方。两端指纹必须都是 `750eeaa9…`。

导出签名 PEM（换机器重建时必做）：
```bash
keytool -importkeystore -srckeystore ~/.android/debug.keystore -srcstorepass android \
  -srcalias androiddebugkey -destkeystore /tmp/d.p12 -deststoretype PKCS12 \
  -deststorepass android -destkeypass android
openssl pkcs12 -in /tmp/d.p12 -nodes -nocerts -passin pass:android -out private.pem
openssl pkcs12 -in /tmp/d.p12 -nokeys -passin pass:android -out certificate.pem
# 放到 band_app/sign/debug/ 和 sign/release/ 各一份，删掉 /tmp/d.p12
```

- 手机端：`mzdwidget_build/`（标准 Android Gradle 工程）
- 手环端：`mzdwidget_build/band_app/`（Vela JS 快应用）
  - `src/manifest.json` — 包名、版本、feature 声明
  - `src/app.ux` — 空壳入口（互联在页面 onReady 初始化）
  - `src/pages/index/index.ux` — 解锁/上锁/长按启动界面
  - `sign/debug`、`sign/release` — 从 debug.keystore 导出的 PEM（**私钥，勿外传**）

手环 rpk 重新构建（需 Node.js ≥ 8.10）：
```bash
cd mzdwidget_build/band_app
npm install
npm run release    # 产物 dist/com.example.mzdwidget.release.*.rpk
```
每次重新打 rpk 前若改了签名，`manifest.json` 的 `versionCode` 要 +1，并卸载手环上旧应用。

手机 APK 构建见主 README。互联协议（两端 JSON 格式）见 `band_app/PROTOCOL.md`。

## 红线（勿改）
- 普通短按只开放 unlock/lock；start 必须手环本地长按满 3 秒且携带 `holdMs>=3000`，手机端二次校验后只走 `CarActions.smartStartAndUnlock()` 完整流程，绝不开放裸 start/stall/search。
- 手环指令必须走 CarActions 统一入口，不得新增绕过 token/日志/提示音的直连路径。
- 两端包名与签名必须一致，否则互联失效。
