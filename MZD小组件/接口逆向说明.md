# MZD 手机控车 —— 逆向接口说明

> 来源：`MZD手机控车_26.08.20.01.apk.1`（包名 `com.cxx.a3300kt.jinlan`，版本 26.08.20.01）
> 分析方式：纯静态分析（解包 APK + DEX 反汇编），未运行、未登录、未向服务端发送任何请求。

## 1. 服务端地址

| 项 | 值 | 来源 |
|---|---|---|
| Host | `https://iov.edaoduo.com/aoduo/prod` | `Url.host`（30 字节数组与 `"SmartCar_2026"` 逐字节 XOR 解码）+ `urlType="prod"` |
| API 前缀 | `https://iov.edaoduo.com/aoduo/prod/api/v2` | `Url.baseUrl = host + "/api/v2"` |
| WebSocket | `wss://iov.edaoduo.com/aoduo/prod/ws/` | `Url.ws`（用于车辆状态推送，本小组件不需要） |

## 2. 登录（获取 token / carid）

```
POST {baseUrl}/user/login
Content-Type: application/x-www-form-urlencoded

phone=<手机号>
passwd=<AES 加密后的密码, Base64>
```

- 密码算法：`AES/CBC/PKCS7Padding`，key = `kSTWuwVyH9YCnNnR`，IV = `3138995984284342`，密文 `Base64(NO_WRAP)`。
  （来源：`LQ6/a.c()` → `LQ6/a.b()`，模式常量 1 = ENCRYPT_MODE）
- 返回 JSON（`UserInfo`）：包含 `token`、`carid`、`userid`、`mobile`、`user_role` 等。
  **小组件只需保存 `token` 和 `carid`。**

## 3. 控车（四个功能）

```
POST {baseUrl}/car/ctrl
Content-Type: application/x-www-form-urlencoded

carid=<车辆ID>
ctrl=<指令码>
boot_time=<整数, 可选; >=0 时才发送; 原App远程启动时传 15>
```

四个目标指令码（`ctrl` 字段）：

| 功能 | ctrl 值 |
|---|---|
| 发动 | `start` |
| 熄火 | `stall` |
| 解锁 | `unlock` |
| 上锁 | `lock` |

（其他指令：`search` 寻车、`trunk_toggle` 后备箱、`rise_window` 升窗、`drop_window` 降窗）

> 来源：`CarCtrlActivity.S()/T()`、`VehicleControlWorker.q()`。原 App 自带一个
> `VehicleControlWorker`，从输入数据取 `cmd`（例如 `start`）后调用同一 `/car/ctrl`，
> 发动时 `boot_time=15`。本小组件复用了这套协议。

## 4. 公共请求头（每个请求都要带）

来源：`RxHttpManager.lambda$init$1()` 与 `getmySignature()`。

| Header | 值 |
|---|---|
| `token` | 登录返回的 token |
| `timestamp` | 当前 Unix 秒时间戳（字符串） |
| `nonce` | `"aod12346" + 随机整数(0..2^31-1)` |
| `signature` | 见下 |
| `apiver` | `v3` |
| `X-App-Identifier` | `"00010800020004" + versionCode` = `0001080002000426082001` |

**signature 计算：**

1. 构造待签名项列表：
   - `"timestamp=" + timestamp`
   - `"nonce=aod12346" + 随机整数`（注意：与 nonce 头一致的随机数）
   - 若 URL 带 query，把 query 按 `&` 拆分后逐项加入（`/car/ctrl`、`/user/login` 无 query，故跳过）
2. 对列表按字符串字典序排序（`Collections.sort`）
3. 按顺序拼接：`逐项 + "&"`（每一项后面都跟一个 `&`）
4. 末尾追加 `token`
5. `MD5`（`Ld4/h.b()` → `d4/h.a()` 用 `MessageDigest("MD5")`），结果转小写十六进制

即：`signature = MD5( sort(["timestamp="+ts, "nonce=aod12346"+rand]) 各项+"&" 拼接 + token ).toLowerCase()`

## 5. 车辆状态查询（小组件左侧显示）

```
GET {baseUrl}/car/status?carid=<车辆ID>
```
（来源：`Url.carStatus = "/car/status"`，`VehicleStatusWorker.v()` 用 `RxHttp.get` + `carid` 参数）

返回 `CarStatus`，关键字段与判定（来源：`VehicleStatusWorker.t()`、`Q6/c.e/f/b()`）：

| 字段 | 含义 / 判定 |
|---|---|
| `engine` | `== 3` 表示发动机已启动 |
| `lock` | `lf/lr/rf/rr` 任一 `== 1` 表示未上锁，否则已锁 |
| `door` | 四个门 `== 1` 表示有门打开 |
| `window` | 六个窗字段 `== 1` 表示有窗打开 |
| `oil` | 油量/续航（字符串） |
| `mileage` | 里程（字符串） |
| `online` | 在线状态 |
| `temp_in` / `temp_out` | 车内/外温度 |

> GET 请求的 query 参数（如 `carid=xxx`）参与 signature 计算：与 `timestamp=`/`nonce=` 一起排序后用 `&` 拼接，末尾追加 token 再 MD5。

## 6. 原 App 的凭证存储（用于提取 token）

来源：`UsualParams.setToken()` / `setCarid()` / `getToken()`。

- 存储组件：**腾讯 MMKV 默认实例**（`MMKV.n()` → `getDefaultMMKV`）
- key：`smart_car_token`（token）、`car_id`（carid）、`user_id`（userid）
- 文件路径：`/data/data/com.cxx.a3300kt.jinlan/files/mmkv/mmkv.default`
- 提取方法见 `提取原App的Token/README.md`

## 7. 已知局限 / 风险提示

- 服务端可能有额外的设备指纹/证书校验（App 内有签名校验 `SHA256=DA9BEECC...`、`X-App-Identifier`、模拟器检测 `Q6/x.d()`）。本小组件尽量复刻了可见请求头，但如果服务端强校验 App 签名，则独立客户端可能无法通过——届时需要改为「复用原 App」或抓包核对真实请求。
- `carid` 可能对应多个车辆；小组件取登录返回的主车 `carid`。
- 请仅在自己的账号与车辆上使用；token/密码仅本地存储，本实现不含任何上传逻辑。
